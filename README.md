# VyaparGuard (व्यापार गार्ड)
> **"Know your cash. Act before the shortage."**

VyaparGuard is a proactive cash-flow risk intelligence platform designed specifically for Indian small businesses (kiranas, retail merchants, wholesalers, and MSMEs). It moves small businesses from backward-looking accounting to forward-looking liquidity defense—detecting working capital shortages before they happen and recommending concrete actions to prevent them.

---

## ⚠️ Problem

Indian small businesses frequently fail not due to lack of profitability, but due to unforeseen working capital shortages:
* **Delayed Receivables:** Customers take 30–60 days of informal credit, leading to sudden liquidity crunches.
* **Inflexible Payables:** Distributors and landlords demand payments on strict due dates under threat of supply cutoff.
* **Blind Spots:** Accounting software only looks at past transactions; business owners lack visibility into their cash balance 5–7 days into the future.
* **LLM Hallucinations:** Generative AI alone cannot be trusted with mathematical cash forecasts or critical financial numbers.

---

## 💡 Solution

VyaparGuard combines a **deterministic Java financial engine** with a **tool-calling AI Agent**:
1. **Mathematical Certainty:** Inflows, outflows, receivables, payables, and 7-day daily cash projections are calculated strictly by deterministic Java algorithms—never by LLMs.
2. **Proactive Shortage Detection:** Alerts the owner days in advance when projected balance breaches their minimum safety threshold (e.g. ₹50,000).
3. **Agentic Tool Calling:** The AI Agent understands user intent, executes backend tools to fetch verified numbers, and provides synthesized guidance.
4. **What-If Simulations:** Live sandbox to simulate delayed payments (e.g. ABC Traders paying 5 days late) or invoice collections.
5. **Database-Backed Action Plans:** Proposed actions generated by the agent can be Approved or Rejected by the owner directly without unauthorized external actions.

## 🧠 Agent Workflow & Deterministic Tools

The AI Agent acts as an intelligent financial advisor that **never hallucinates financial numbers**:

$$\text{User Question} \longrightarrow \text{Intent Parsing} \longrightarrow \text{Tool Calls} \longrightarrow \text{Java Financial Engine} \longrightarrow \text{Structured Response} \longrightarrow \text{Action Plan}$$

### The 5 Agent Tools:
1. `get_cash_position()`: Returns current cash, 7-day projected cash, minimum threshold, shortage amount, and shortage date.
2. `get_overdue_invoices()`: Returns all overdue invoices with customer names, invoice numbers, amounts, and days overdue.
3. `get_upcoming_payments()`: Returns upcoming supplier obligations with amounts, due dates, and categories.
4. `run_cashflow_scenario(collectionDelayDays, expenseIncreasePercent, targetCustomer)`: Calculates baseline vs. scenario minimum cash, ending cash, and risk severity.
5. `create_action(title, description, priority, category)`: Persists proposed actions to PostgreSQL for user approval.

### Graceful Key Handling:
When no `LLM_API_KEY` is present, the app gracefully returns:
> *"AI assistant requires an LLM API key. Financial dashboard remains available."*
All dashboard metrics, charts, and direct deterministic tools remain 100% accessible.

## 🛠️ Tech Stack

* **Frontend:** React 18, Vite, TypeScript, Tailwind CSS, Recharts, Lucide Icons
* **Backend:** Spring Boot (Java 17), Spring Data JPA, Hibernate, Apache Commons CSV
* **Database:** PostgreSQL (with auto-detecting embedded fallback for zero-config local development)
* **AI:** Google Gemini (`gemini-1.5-flash`) / OpenAI (`gpt-4o-mini`) Function Calling
* **Containerization:** Docker, Docker Compose, Multi-stage Dockerfiles, Nginx

## 🚀 Setup & Startup

### Option 1: Docker Compose (Production Ready)
```bash
docker-compose up --build
```
* **Frontend:** `http://localhost:3000`
* **Backend API:** `http://localhost:8080/api/dashboard`
* **PostgreSQL:** `localhost:5432`

### Option 2: 1-Click Windows Startup (Local Dev)
Double-click `start-all.bat` or run:
```powershell
.\start-all.bat
```

### Option 3: Manual Startup

**Backend:**
```powershell
cd backend
$env:JAVA_HOME = "..\.tools\jdk17.0.20_12"
..\.tools\apache-maven-3.9.6\bin\mvn spring-boot:run
```

**Frontend:**
```powershell
cd frontend
npm install
npm run dev
```
* Frontend live at: `http://localhost:5173`
* Backend live at: `http://localhost:8080`

## 🎬 Live Hackathon Demo Script (Sri Lakshmi General Stores)

Follow this exact flow during your demonstration:

### Step 1: Open Dashboard (`http://localhost:5173`)
1. **Show Current Cash:** Notice **₹1,22,600** — the business appears healthy on the surface.
2. **Show Overdue Receivables:** **₹85,000** overdue across 4 key customers (Mehta Kirana Mart, ABC Traders, etc.).
3. **Show Upcoming Payments:** **₹1,50,500** due to FMCG suppliers within the next 14 days.
4. **Show 7-Day Forecast Chart:** Notice the trajectory line plunging below the **₹50,000** safety threshold on **October 5**, bottoming out at **₹12,600**.
5. **Show Risk Alert Card:** *"Cash Shortage Risk Detected: Projected balance falls to ₹12,600, below your ₹50,000 safety threshold on October 5, 2026 (₹37,400 deficit)."*

### Step 2: Open AI Agent Tab ("Ask VyaparGuard")
1. Click the suggested chip: **"Will I have enough cash next week?"**
   * *Observation:* Agent invokes `get_cash_position()`, displays verified numbers, flags **HIGH** risk, and notes the exact ₹37,400 deficit on October 5 without hallucinating.

2. Click the suggested chip: **"What happens if ABC Traders pays 5 days late?"**
   * *Observation:* Agent identifies ABC Traders' ₹30,000 overdue invoice, invokes `run_cashflow_scenario()`, and renders a side-by-side **Baseline vs. 5-Day Delay** comparison table showing liquidity dropping to critical levels.

3. Click the suggested chip: **"What should I do today?"**
   * *Observation:* Agent runs inspection tools and invokes `create_action()` to generate 2–3 concrete prioritized actions stored in the database:
     * **HIGH:** Follow up with ABC Traders regarding ₹30,000 overdue invoice.
     * **MEDIUM:** Review supplier payment to ITC Distribution Hub (₹42,000) due Oct 3.
     * **LOW:** Pause non-essential discretionary expenses.

4. **Approve an Action:**
   * In the **Agent Proposed Action Plan** section below, click **Approve** on the ABC Traders follow-up task.
   * *Observation:* Status updates immediately from `PROPOSED` to `APPROVED` in PostgreSQL.

### Step 3: What-If Scenarios Tab
1. Select **Mehta Kirana Mart (₹24,500)** to collect.
2. Select **ITC Distribution Hub (₹42,000)** to defer by 7 days.
3. Watch the trajectory line instantly lift above the ₹50,000 threshold, showing a healthy **₹97,100** projected balance!

## 📡 REST API Reference

| Endpoint | Method | Description |
| :--- | :--- | :--- |
| `GET /api/dashboard` | `GET` | Dashboard summary (cash, receivables, payables, 7-day forecast, risk message) |
| `GET /api/cashflow` | `GET` | 7-day historical & 7-day forward projected cash trajectory |
| `GET /api/invoices/overdue` | `GET` | List of overdue customer invoices |
| `GET /api/payments/upcoming`| `GET` | List of upcoming trade supplier payments |

| `GET /api/agent/actions` | `GET` | List all database-stored proposed actions |
| `POST /api/agent/actions/{id}/approve` | `POST` | Approve proposed action in database |
| `POST /api/agent/actions/{id}/reject` | `POST` | Reject proposed action in database |
| `GET /api/agent/tools/cash-position` | `GET` | Deterministic Tool 1: Cash position |
| `GET /api/agent/tools/overdue-invoices` | `GET` | Deterministic Tool 2: Overdue invoices |
| `GET /api/agent/tools/upcoming-payments` | `GET` | Deterministic Tool 3: Upcoming payments |
| `POST /api/agent/tools/run-scenario` | `POST` | Deterministic Tool 4: Cashflow scenario |
| `POST /api/agent/tools/create-action` | `POST` | Deterministic Tool 5: Create proposed action |
| `POST /api/scenarios/simulate` | `POST` | What-If sandbox simulation engine |

| `POST /api/demo/reset` | `POST` | Reset demo state to initial Sri Lakshmi General Stores |
